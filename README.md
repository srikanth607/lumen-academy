# Lumen Academy — server-backed website

This package turns the uploaded Lumen Academy HTML prototype into a same-origin website with a real server, SQLite database and server-side login sessions.

## What is connected

- Account creation and login are handled by the server (not browser storage).
- Passwords are hashed with bcrypt; plaintext passwords are never stored.
- Login sessions are stored server-side in SQLite and use HttpOnly, SameSite cookies.
- Login attempts are rate-limited; state-changing requests use a CSRF token and same-origin check.
- Roles are assigned by the server. Public sign-up can only create student accounts. Staff accounts require a one-use invite code generated by the owner dashboard.
- Student chapter completion, staff announcements, invitation codes and user administration are persisted in SQLite.
- Owner-only operations are checked on the server; hiding a button in the browser is not the security boundary.

## Run locally (Windows, macOS or Linux)

1. Install **Node.js 20 or newer**.
2. Open a terminal in this `lumen-backend` folder.
3. Copy `.env.example` to `.env`.
   - Windows PowerShell: `Copy-Item .env.example .env`
   - macOS/Linux: `cp .env.example .env`
4. Edit `.env`. Set a unique `SESSION_SECRET` (at least 32 characters), `OWNER_NAME`, `OWNER_EMAIL`, and a strong `OWNER_PASSWORD` (at least 12 characters). Do not share `.env` or upload it to GitHub.
5. Install packages: `npm install`
6. Start: `npm start`
7. Open **http://localhost:3000**. Sign in using the owner email/password you set in `.env`.

The first server start creates the owner account. The SQLite database is created in `data/`. Keep that folder backed up; it contains accounts, sessions and learning records. Do not delete it to restart the server unless you intend to erase the site's data.

## Create staff accounts

1. Log in with the owner account.
2. Open **My panel** → **Create an invitation**.
3. Generate a Teacher, Coordinator or Principal code.
4. Give the code to the intended person. They enter it on the Create account page. Codes are single-use.

Normal public registration creates a student account. No one can select their own staff role from the browser.

## Deploy to the internet

Deploy the entire folder to a Node.js host that supports persistent disk storage. Set the environment variables in the host dashboard; do not upload `.env`. Set `NODE_ENV=production`, use HTTPS, and set `TRUST_PROXY=1` only if your host's trusted reverse proxy terminates HTTPS. Ensure the `data/` directory is on persistent storage and is backed up. Point your domain to the app and serve it over HTTPS only.

Do not use ephemeral/serverless storage for this SQLite configuration. For multiple app instances, move to a managed shared database and shared session store before scaling horizontally.

## Important before a public school launch

This is a functional starter backend, not a completed security/compliance audit. Before inviting real students, add and test email verification, password reset, account recovery, audit logs, retention/deletion rules, database backups/restore, monitoring, and a privacy notice/consent flow appropriate to your school and local law. The app currently uses a local SQLite database and does not send email. Have a qualified developer review the deployment and access rules.

## Files

- `public/index.html` — your Lumen Academy website, wired to the backend API.
- `server.js` — Express API, authentication, permissions and database setup.
- `data/lumen.sqlite` — created automatically on first run; not included in this package.

## Deploy on Render (recommended first deployment)

1. Create a **private** GitHub repository and upload the *contents* of this folder to the repository root: `server.js`, `package.json`, `.gitignore`, `.env.example`, `public/`, and this README. Do not upload `.env`, `node_modules/`, or any `data/` database files.
2. Create a Render account and connect GitHub. In Render choose **New → Web Service**, select the private repository, and set:
   - Runtime: Node
   - Build command: `npm install`
   - Start command: `npm start`
   - Instance type: a paid instance that supports persistent disks (free instances cannot attach a persistent disk).
3. In the service's **Advanced** settings, add a persistent disk:
   - Mount path: `/opt/render/project/src/data`
   - Size: choose the smallest available size that meets your needs.
   The app stores both `lumen.sqlite` and `sessions.sqlite` in its `data/` folder, so this exact mount path keeps both files across restarts and deploys. If you change the repository's Root Directory, the mount path must be adjusted to the actual deployed project path.
4. Add these environment variables in Render (never put secrets in GitHub):
   - `NODE_ENV` = `production`
   - `TRUST_PROXY` = `1`
   - `SESSION_SECRET` = a unique random secret of at least 32 characters
   - `OWNER_NAME` = your chosen site-owner display name
   - `OWNER_EMAIL` = your owner login email
   - `OWNER_PASSWORD` = a unique password of at least 12 characters
5. Create the Web Service and wait for the first deploy to finish. Render gives the service an `https://<service-name>.onrender.com` address; a custom domain is optional.
6. Test owner login, student registration, logout/login, chapter progress, and invite-code creation. Keep regular backups of the persistent disk/database.

**Cost and suitability:** Render's free web services have an ephemeral filesystem and spin down after inactivity; persistent disks require a paid service. Free Render Postgres databases expire after 30 days. Therefore, do not use a free ephemeral service for real student accounts or learning records. Check Render's current pricing before creating paid resources. This starter app has not had an independent security/compliance audit; complete the privacy, backup, recovery, and school-consent work described above before inviting real students.
